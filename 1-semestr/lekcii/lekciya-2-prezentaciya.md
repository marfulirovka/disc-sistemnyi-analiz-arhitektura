## Слайд 4. Что такое система

- What is a system
- Классическое определение — Elements and links — Совокупность взаимосвязанных элементов, которая образует целостность и обладает свойствами, которых нет у отдельных элементов
- Прагматическое определение — Boundary and environment — Выделенный фрагмент мира, у которого есть граница и который взаимодействует со своим окружением
- Связность — Connectedness — По связям можно «дойти» от любого элемента до любого другого
- Целостность — Wholeness — У совокупности есть свойство, которого нет ни у одного элемента
- Вопрос не в том, «является ли» объект системой, а в том, полезно ли так на него смотреть для вашей задачи — The question is not whether it is a system, but whether it is useful to see it as one.

## Слайд 5. Граница системы

- System boundary

| Вид границы / Boundary | Пример | Когда удобна |
|---|---|---|
| Физическая | Стены здания, территория склада | Безопасность, логистика |
| Административная | Зона ответственности отдела, юридическое лицо | Управление, отчётность |
| Логическая | Все, кто участвует в обслуживании клиента, из любых отделов | Процессы, клиентский опыт |
| Временная | Жизненный цикл проекта, сезон, отчётный период | Проекты |

- Правило (под запись). Границу проводят от цели рассмотрения и интересов стейкхолдеров, а не по оргструктуре. Граница по одному отделу отрезает причины на стыке — Draw the boundary from the purpose of analysis, not from the org chart.

## Слайд 6. Окружение, надсистема, подсистема

- Environment, supersystem, subsystem
- Окружение: пациенты, городской портал записи, страховая компания
- Надсистема: городское здравоохранение
- Система: поликлиника (путь пациента)
- Подсистема — Регистратура
- Подсистема — Приём врачей
- Подсистема — Диагностика
- Связи: запись → приём → назначения → повторный визит
- Окружение — Environment — Всё, что не входит в систему, но влияет на неё или испытывает её влияние
- Надсистема — Supersystem — Более крупная система, частью которой является наша
- Подсистема — Subsystem — Часть системы со свойствами системы и собственной подцелью

## Слайд 7. Мини-задание: две границы одной задачи

- Pair task: two boundaries
- Задача: почему клиенты банка жалуются на долгое оформление кредита?
- Граница А: кредитный отдел — Boundary A — Что попадёт внутрь? Какие причины задержки вы увидите, а какие останутся за границей?
- Граница Б: путь клиента — Boundary B — От заявки на сайте до выдачи денег: отделение, кредитный отдел, служба безопасности, ИТ
- В парах, 5 минут. Сравните: какая граница полезнее для этой задачи и почему? — Compare: which boundary is more useful for this problem, and why?

## Слайд 8. Элемент и подсистема

- Element and subsystem
- Элемент — предел деления — Element — Часть, внутреннее устройство которой для задачи неважно. Для загрузки поликлиники элемент — врач; для качества диагностики — его квалификация, время приёма, доступ к анализам
- Подсистема — часть с подцелью — Subsystem — Регистратура — подсистема: её подцель — распределить пациентов по врачам. «Все сотрудники третьего этажа» — не подсистема, а случайная группа
- Где остановить деление, решает задача, а не устройство объекта — The task, not the object, decides where decomposition stops.

## Слайд 9. Связи между элементами

- Links
- Связь — важный для задачи обмен между элементами: веществом, энергией, информацией, а в организации — также деньгами и людьми.

| Признак / Feature | Варианты | Пример в организации |
|---|---|---|
| Направление | Направленные и ненаправленные | Приказ — сверху вниз; обсуждение на совещании — в обе стороны |
| Сила | Сильные и слабые | Ежедневная передача заказов складу — сильная; годовой отчёт — слабая |
| Характер | Подчинения, управления, равноправные, порождения | Руководитель — сотрудник; договор двух компаний |

- Перечислить элементы мало: система видна только тогда, когда показаны связи — Listing elements is not enough: the system appears only when links are shown.

## Слайд 10. Обратная связь: две петли

- Balancing and reinforcing feedback
- Балансирующая петля (B) — Balancing loop: returns the system to its goal
  - Запасы на складе выросли → заказы поставщику сокращаются → поступления уменьшаются → запасы возвращаются к норме
- Усиливающая петля (R) — Reinforcing loop: amplifies change
  - Довольные клиенты рекомендуют → клиентов становится больше → растёт выручка и вложения в сервис → довольных клиентов ещё больше
- Усиливающая петля работает в обе стороны: недовольство раскручивается так же быстро. Петли — главный инструмент лекции 4 — A reinforcing loop works both ways. Loops are the key tool of lecture 4.

## Слайд 11. Структура и поведение системы

- Structure, state, behaviour
- Линейная — Linear — Последовательная цепочка: конвейер, согласование документа
- Иерархическая — Hierarchical — Уровни подчинения: оргструктура, структура бюджета
- Сетевая — Network — Многие связаны со многими: проектная команда, партнёрская сеть
- Матричная — Matrix — Двойное подчинение: по функции и по проекту
- Под запись. Структура — устойчивые связи, которые сохраняются, когда люди меняются. Состояние — «снимок» системы; поведение — переход между состояниями; цель — желаемое состояние — Structure: stable links. State: a snapshot. Behaviour: moving between states. Goal: the desired state.

## Слайд 12. Системные свойства

- System properties

| Свойство / Property | Суть | Пример |
|---|---|---|
| Целостность | Изменение одной части отражается на других | Смена программы учёта меняет работу бухгалтерии, склада и продаж |
| Эмерджентность | У целого есть новое качество, которого нет у частей | «Доставка за два часа» — свойство службы доставки, а не курьера |
| Иерархичность | Система — часть надсистемы и состоит из подсистем | Кафедра — факультет — университет — высшее образование |
| Синергия | Совместный результат больше суммы вкладов | Слаженная команда быстрее тех же людей поодиночке |

- Внимание. Синергия — «вместе больше», эмерджентность — «вместе иначе». Бюрократия и очереди — тоже эмерджентные свойства — Synergy: more together. Emergence: different together.

## Слайд 13. Классификация систем

- Classifying systems

| Признак / Criterion | Виды | Что это значит для анализа организации |
|---|---|---|
| Происхождение | Естественные / искусственные | Организацию создали люди с какими-то целями |
| Связь со средой | Открытые / закрытые | Организация обменивается с рынком, государством, обществом |
| Сложность | Простые / сложные / большие | Полностью не описать — нужны модели под задачу |
| Предсказуемость | Детерминированные / вероятностные | Поведение людей вероятностно: прогноз — диапазон |
| Элементы | Пассивные / активные | У людей свои цели, они могут противодействовать |
| Связи | Жёсткие / мягкие | Мягкие системы изучают через точки зрения участников |

- Практическое следствие. Организация — искусственная, открытая, сложная, вероятностная, с активными элементами и мягкая — Analysis starts with boundaries and viewpoints, not with calculations.

## Слайд 14. Закон необходимого разнообразия

- Ashby's law of requisite variety
- Сложные социально-экономические системы — Complex socio-economic systems — Много элементов и связей; неопределённость; люди со своими целями; полное описание невозможно; нынешнее устройство — след прошлых решений
- У. Р. Эшби: Управляющая система справляется с возмущениями, только если её разнообразие — число вариантов реакции — не меньше разнообразия возмущений — Only variety can absorb variety.
- Два пути — Two options — Больше вариантов управления (полномочия, обучение) или меньше разнообразия объекта (стандарты)
- Поэтому жёсткий регламент с одним вариантом действий не работает в меняющейся среде — A rigid one-option procedure fails in a changing environment.

## Слайд 15. Типовые ошибки при описании системы

- Common mistakes
- 1. Система — «всё подряд»: граница не проведена
- 2. Граница по оргструктуре, хотя проблема лежит на стыке подразделений
- 3. Элементы без связей: перечислены части, но не показано, как они взаимодействуют
- 4. Эмерджентность одного элемента: «квалифицированный врач» — свойство части, а не целого
- 5. Нет окружения: система описана так, будто существует в пустоте

## Слайд 16. Разбор: поликлиника как система

- Case: a clinic as a system
- Разбор учебный. Цель рассмотрения — понять, почему онлайн-запись не сделала помощь доступнее. Поэтому граница проведена по пути пациента, а не по зданию.

| Понятие | Для поликлиники | Почему так |
|---|---|---|
| Граница | Путь пациента: запись → приём → назначения → повторный визит | Доступность не ограничена стенами |
| Элемент окружения | Городской портал записи | Влияет, но поликлиника им не управляет |
| Обратная связь | Больше неявок → ручная перезапись → меньше окон онлайн | Результат меняет поведение системы |
| Эмерджентность | Доступность медицинской помощи | Её нет у врача или регистратуры отдельно |

- Это фрагмент — по строке на понятие. Полное описание своего объекта вы составляете на практиках 3–4 — A fragment only; you describe your own object in full in class.
